# Wildshape 1.0.5 concurrency and allocation audit

Baseline: remote `fix/worldgen-performance-1.0.4`, commit `256e003`. Scope: the shared terrain caches, resource pools, density sampling, erosion kernels and surface strata. This document records source findings; the final release verification report owns actual build/test results.

## Corrected findings

- **Lazy result publication race.** `LazyCallable.call` read its value, validated an optimistic stamp, and only then checked completion. A writer could complete between the stamp validation and completion read, allowing the reader to return its old null local value. A volatile completion flag is now read before its published value; first initialization still uses the existing write lock. Null results remain valid completed values. This also removes stamped read-lock work from completed cache entries.

- **Mutable surface RNG shared between workers.** `MixinSurfaceSystem` cached strata in a concurrent map but forked every new key from one mutable `RandomSource`. Different keys can be initialized concurrently and in different orders. Each strata resource key now receives its own random sequence from a positional random factory. This removes that shared RNG race and first-use-order dependency. The change intentionally changes rock-layer selections in newly generated chunks. Existing chunks are not rewritten; underlying terrain noise and saved presets are unchanged by this fix.
- **Two allocations on each density column cache miss.** `CellSampler.Cache2d` replaced its weak world reference with an empty reference, then with a world reference, every time coordinates changed. Position invalidation already guards failure publication. The same weak world identity is now retained across position changes; it is replaced only for a different world. Failed lookups still cannot publish a partial cell, and the reference still permits closed worlds to be reclaimed.
- **Duplicate erosion kernels retained per column.** Radius-four erosion brushes previously retained one absolute-index and one weight array for every tile column. Equal edge clipping patterns now share immutable relative offsets and weights. At most 81 pairs are retained regardless of tile area, plus the two existing column lookup tables. Loop order and float weight arithmetic match the legacy implementation exactly. The per-drop scratch values and PRNG remain local to each erosion invocation; kernels are read-only after publication.
- **Thread-local Cell pool bookkeeping.** The pool skipped slot zero and its close method could return one active object twice. It now borrows every preallocated slot, tracks release state, and cleans/returns each lease once until borrowed again. A return from a different worker is cleaned and discarded rather than mutating the owner's unsynchronized thread-local list. Resource ownership remains scoped: a caller must not use a handle after closing it or close an old handle after it has been borrowed again.

## Preserved safeguards

The 1.0.2 timestamp snapshot in `Cache.trimWithoutClosing` already prevents the TimSort comparator race. Tile cache eviction must continue to forget published tiles without recycling their cell arrays: `WorldLookup`, density samplers and asynchronous chunk readers can still reference them. Failed tiles remain retryable, and an unfinished tile is not selected as an eviction candidate. Shared map contents are protected by read/write locks; tile eviction order is not used as a worldgen seed.

The 1.0.4 structure-search path and SkyLands remote probes already prevent full filtered tile preparation during broad searches. Worldgen has a separate executor; it is not safe to block every executor worker waiting for child tasks submitted to the same fixed-size executor. No semaphore/backpressure that could introduce that starvation cycle was added.

Thread-local noise caches are world-context-owned or key their last lookup by weak world identity. Thread-local site grids have entry limits. Bulk cache clearing in several landform grids can still cause CPU spikes; changing their cache strategy requires a separate benchmark, not unverified arithmetic shortcuts. Mutable global worldgen flags are scoped thread-locally and restored with `finally` in existing code.

## Remaining measurable costs and limits

Cold tile preparation still includes terrain, climate, drainage, erosion and smoothing over the tile and its border. This audit does not establish a full-pack TPS improvement or remove cold generation latency. The configured Streams watershed survey remains a separate potential first-use cost. `Heightmap.sampleGround`, `sampleTerrain` and `sampleDrainageGround` still allocate temporary Cells; replacing those return values needs explicit nested-call ownership and equivalence checks. Feature/template placement legitimately creates immutable BlockPos values when downstream consumers retain them. This implementation does not claim a zero-allocation generator.

The fixed worldgen executor queue remains unbounded: limiting outstanding futures correctly requires cooperative scheduling and generation lifecycle support. Bounded retained completed tiles are not a bound on every concurrently requested in-flight tile. Worker ThreadLocals can retain per-context data until those workers are reused or stop; server lifecycle cleanup needs testing across client world switching before replacing the existing process-wide executors.

## Cleanup inventory

`LoadBalanceLongMap` has no production or test callers in this repository. It is a public class, so removing it could break external callers; it is retained and flagged for a future API removal. Its unused implementation has a non-power-of-two stripe calculation and should not be adopted without correction/tests. Legacy `fabric/` source is excluded from the current NeoForge release build, but is retained as port material. Deprecated Cell fields and heightmap markers participate in serialization, terrain derivation or compatibility and were not deleted based only on deprecation annotations. Broad conversion of legacy config APIs was not mixed into concurrency fixes because saved config/preset identity must be preserved.

No dead class or mixin was deleted solely because a text search found no direct Java caller: codecs, mixin JSON, registry bootstrap and datapack resources can reference those types indirectly.
